# Photon architecture

Photon is plain C on GTK3 + GtkSourceView 4 + VTE. Each file in `src/` owns
one job and says so in the comment at its top. There are no globals: the
window's state lives in a `PhotonApp` (see `app.h`), and every callback gets
it as `user_data`.

```
src/main.c         startup: parse the command line, then either the launcher
                   (cli.c) or the window here: data folder, photon_app_new()
src/cli.c/.h       the command line, and the `photon` launcher: makes paths
                   absolute, hands files to the running Photon or starts a
                   detached one, waits for -w; never touches GTK
src/remote.c/.h    one Photon at a time: a Unix socket (own thread + GMainContext,
                   off GTK's loop) taking "open/run/wait/close/list" requests
src/app.c/.h       main window: layout, documents (new/open/save/close/quit +
                   "unsaved changes?"), session, zoom, showing run errors
src/menus.c/.h     the menu bar and EVERY shortcut (one line per item)
src/tabs.c/.h      notebook of open documents: labels, "*" dirty mark, close
                   buttons, find-by-path
src/document.c/.h  one open file: buffer + view + path + language + dirty
                   state + error markers; editor defaults (auto-indent, ...)
src/editing.c/.h   typing behaviors from the language: auto-close pairs,
                   smart Enter, dedent on "}", comments, duplicate/move lines
src/search.c/.h    find/replace bar (GtkSourceSearchContext) + go to line
src/completion.c/.h autocomplete: buffer words + the language's keywords
src/sidebar.c/.h   file tree on the left (lazy; refreshes after saves)
src/panel.c/.h     bottom notebook; owns the "Terminal" tab (user's shell)
src/runner.c/.h    Run / Stop: builds the command, runs it in the "Run" tab,
                   tees stderr, exit code + time, finds lunar/python3/cc
src/errors.c/.h    stderr parsers (Lunar, gcc/clang, Python) -> PhotonError list
src/languages.c/.h the language registry (one entry per language)
src/statusbar.c/.h message, Ln/Col, language picker, run status
src/settings.c/.h  settings.ini (GKeyFile) in g_get_user_config_dir()/photon:
                   [tools] lunar=, [session] files= current=, [editor] font_size=
src/theme.c/.h     theme registry (6 themes, most of them palettes for one Win95
                   CSS template): chrome CSS, code
                   scheme, terminal colors/font; restyles attached buffers and
                   terminals on a switch; font zoom
src/about.c/.h     the About Photon dialog
src/fontdialog.c/.h View > Fonts...: code + interface font pickers, live preview;
                   the choice lives in theme.c (PhotonFonts) and settings [fonts]
src/platform.c/.h  ALL OS-specific code (#ifdef __APPLE__ / __linux__), incl.
                   starting a detached Photon (setsid, or `open -a Photon.app`),
                   the socket folder and the log redirect

lang/             GtkSourceView language specs (lunar.lang)
styles/           GtkSourceView style schemes, one per theme (<theme id>.xml)
icons/            app icon at every size + photon.icns, generated by
                  tools/make_icon.py (32x32 pixel art kept as text)
data/             photon.desktop (Linux), Info.plist.in + photon-launcher.sh
                  (macOS Photon.app: the launcher gives Finder-started Photon
                  the login shell's PATH and starts it in ~)
install.sh        installer for both OSes; wraps make install / make install-app
tests/samples/    small Lunar / C / Python files for manual and CI checks
tests/test_*.c    unit tests (`make test`): parsers, editing, markers, registry,
                  tabs + session + sidebar through a real PhotonApp
```

How it fits together:

```
main ──> platform_init() + platform_data_dir() ──> languages_init() + theme_new()
     └─> app_new(options)
           ├─ settings_load()
           ├─ statusbar_new()   bottom strip; language picker calls back
           ├─ completion_new()  shared "Words" provider + one per language
           ├─ tabs_new()        documents; tells the app about switches/closes
           ├─ search_new()      find bar, searches app_current_doc()
           ├─ panel_new()       bottom notebook: Terminal tab (hidden at start)
           ├─ runner_new()      adds the Run tab to the panel
           ├─ sidebar_new()     file tree (left), calls back app_open_file()
           ├─ menus_build()     menu bar + shortcuts
           └─ restore session, open the file from the command line

A new document goes through app.c add_document(): theme_attach_buffer(),
completion_attach(), cursor -> status bar, tabs_add(). editing.c is
attached by document_new() itself.
```

A run, start to finish:

```
Run (Cmd/Ctrl+R, F5) -> runner_run()
  app_save()                         asks for a name if untitled
  language = document_get_language() registry entry for the file
  command  = run_cmd with {file} {exe} {lunar} ... expanded and quoted
             ({lunar}: $LUNAR, settings.ini [tools] lunar=, PATH, then ask)
  /bin/sh RUN_WRAPPER err-file command   in the Run tab's VteTerminal
        stdin/stdout on the terminal, stderr tee'd to err-file
child-exited -> "[Exit N · 0.42 s]", status bar
  errors = language->error_parser(err-file text)
  app_show_errors(): open the file of the first error, mark lines, jump
Any edit in the document clears its markers.
```

Each module follows the same shape: an opaque struct (`PhotonSidebar`, ...),
`photon_<module>_new()` / `_free()`, `_get_widget()` for the root widget the
app packs into the layout, and a few verbs (`photon_panel_toggle()`, ...).
A module never includes `app.h` unless it really needs the whole app.

### Data files at runtime

Nothing has to be installed for highlighting. At startup
`photon_platform_data_dir()` finds the folder holding `lang/` and `styles/`
by checking, in order: `$PHOTON_DATA_DIR`, the folder of the executable
(running `./Photon` from the repo), its parent, `<prefix>/share/photon`
next to an installed binary, and finally the compiled-in `PHOTON_DATADIR`.
`lang/` is put **first** in GtkSourceView's search path, so the repo's
`lunar.lang` beats an older copy in `~/.local/share/gtksourceview-4`.

### Rules

- Shortcuts are always written with `<Primary>` (Cmd on macOS, Ctrl on Linux),
  and all of them live in `menus.c`. Avoid Cmd+H / Cmd+M (macOS) and
  Ctrl+Alt+arrows (Linux). On Linux a focused terminal gets Ctrl+keys first
  (see `on_window_key_press()` in app.c), so Ctrl+C still interrupts.
- `#ifdef __APPLE__` / `__linux__` only in `platform.c`.
- Paths are built with `g_build_filename()`; temp/config dirs come from
  `g_get_tmp_dir()` / `g_get_user_config_dir()`; programs are found with
  `g_find_program_in_path()`. Never hardcode `/tmp`, `~/.config` or
  `/opt/homebrew`.
- Every font list ends in something both OSes have (Menlo, DejaVu Sans Mono,
  Liberation Mono, `monospace`).
- `make WERROR=1` must build with zero warnings (CI does this on Linux and macOS).
  Unused callback parameters are marked `G_GNUC_UNUSED`.

## How to add a feature

1. Decide which module owns it. New area of the UI? New module:
   `src/thing.c` + `src/thing.h` with the header comment, an opaque
   `PhotonThing`, and `photon_thing_new/free/get_widget`.
2. If the window needs to hold it, add a field to `PhotonApp` in `app.h`,
   create it in `create_modules()` (app.c) and free it in `photon_app_free()`.
3. The Makefile compiles every `src/*.c`, so there is nothing to register.
4. `make WERROR=1 && make check`.

## How to add a menu item + shortcut

In `menus.c`, write a callback:

```c
static void
on_reload(GtkWidget *item G_GNUC_UNUSED, gpointer user_data) {
    PhotonApp *app = user_data;
    ...
}
```

and add one line to the matching `build_*_menu()` function:

```c
add_item(menu, accel, "Reload", "<Primary><Shift>r", G_CALLBACK(on_reload), app);
```

Pass `NULL` as the shortcut for a menu item without one.

## How to add a language

Add ONE entry to `LANGUAGES` in `src/languages.c`:

```c
static const PhotonLanguage LANG_RUBY = {
    .id = "ruby", .name = "Ruby",
    .exts = { ".rb", NULL },
    .gsv_lang = "ruby",               // GtkSourceView language id
    .run_cmd = "{ruby} {file}",       // NULL if it can't be run
    .comment = "#", .indent = 2,
    .pairs = "()[]{}\"\"''",           // auto-close pairs, 2 chars each
    .error_parser = NULL,             // or a parser from errors.c
};
...
static const PhotonLanguage *const LANGUAGES[] = { &LANG_LUNAR, &LANG_C, &LANG_PYTHON, &LANG_RUBY, NULL };
```

Then, only if needed:

- **A new `{tool}` in run_cmd**: add a line to `TOOLS` in `runner.c`
  (`{ "ruby", "RUBY", { "ruby", NULL }, FALSE }` = env var, PATH names,
  whether to ask with a file chooser when it isn't found).
- **Error markers**: write `photon_errors_parse_ruby()` in `errors.c`
  (text in, `PhotonError` list out; see the Python one) and add a test
  case with real output to `tests/test_errors.c`.
- **No GtkSourceView highlighting for it**: drop `lang/<id>.lang` in the
  repo (copy `lunar.lang`; style ids are `<id>:<name>` and should `map-to`
  a `def:*` style so every scheme colors them).

Run placeholders: `{file}` `{dir}` `{name}` (file name without extension)
`{exe}` (`<tmp>/photon-<name>`) and any tool in `TOOLS`. Every value is
shell-quoted; the command runs in the file's folder.

## How to add a theme

Most themes are a **palette** for the shared Windows 95 template
(`WIN95_CSS` in `src/theme.c`), whose `@name@` tokens are filled in when the
theme is applied:

1. Write a palette, e.g. copy `TURBO_VARS` (silver Win95 chrome via
   `SILVER_CHROME`) or `AMBER_VARS` (a one-color CRT via `CRT_CHROME`), and
   set its colors and fonts. The tokens are listed above `WIN95_CSS`.
2. Add `styles/<id>.xml`, a GtkSourceView scheme. Color the `def:*` styles
   and you cover every language; add `lunar:*` styles for Lunar extras.
   Include `search-match`, or GtkSourceView warns.
3. Add one entry to `THEMES` (palette, scheme id, terminal colors + Pango
   font list, `term_mono` for a one-color terminal, marker colors, title
   strip on/off) and its id to `THEME_IDS`.

It shows up under View > Theme on its own, `photon --theme <id>` tries it,
and `make test` checks that its CSS parses and its scheme loads.

A theme that looks nothing like Windows 95 can skip the template: give it
plain CSS and `.vars = NULL`, like `VSCODE_CSS`. Photon's own widgets have
CSS classes: `.photon-titlebar`, `.photon-statusbar`, `.photon-search`,
`.photon-sunken` (editor / sidebar / terminal wells), `.photon-tab-close`,
`.photon-about-box`, `.photon-about-well`.

## The `photon` command

`photon FILE` runs the same program in **launcher mode** (no GTK): it makes
the paths absolute, connects to the running Photon's socket (remote.c) and
sends `open <path>` lines, then exits. With no Photon running it starts one
with `--detached` (platform.c: its own session on Linux, `open -a Photon.app`
on macOS so the Dock shows it) and exits; the detached window writes its
output to `photon.log` in the cache folder. `photon -w FILE` sends `wait`
and blocks until the reply `closed <path>`, which app.c triggers when that
tab closes (`photon_remote_document_closed`).

The window runs in **GUI mode**: `--detached`, `--foreground`, or the test
flags (`--smoke-test`, `--screenshot`, which never open the socket).
`tests/test_launcher.py` checks the launcher returns within a second.
